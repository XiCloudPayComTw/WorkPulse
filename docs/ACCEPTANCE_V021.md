狀態：待公司實際執行。GitHub CI 僅為合成資料與瀏覽器回歸，不代表正式 Workspace 驗收。先依 [正式部署手冊](DEPLOYMENT_V020.md) 取得公司授權並建立隔離的測試環境。

## 2. 分月完整性驗收

先由持有者執行既有停寫程序（至少 10 分鐘只是門檻，須另外確認舊入口及其他寫入均停止）。在私人管理控制台「分月資料完整性驗收」選擇月份，執行唯讀檢查，下載 JSON 留存。異常列位置只供人工核對，不自動更改。先使用 workPulseVerifyMonthFiles 逐批檢查所有月份的表頭及索引。超過上限請人工分批檢查，空月不算通過。舊資料缺少新版請求時不可直接刪除，須確認原始備份與遷移歷史。

## 3. 月檔復原比對（不修改正式資料）

由公司持有者從已驗證的月備份在獨立私人測試資料夾建立一份副本；確認兩檔均不屬任何日常環境，不要選擇正式控制表或正式月檔。在私人 Apps Script 設定 WORKPULSE_RESTORE_VERIFY_MONTH（YYYY-MM）、WORKPULSE_RESTORE_SOURCE_ID（備份）、WORKPULSE_RESTORE_COPY_ID（復原副本），執行 workPulseCompareRestoredMonth。確認 valuesMatch 與 stableDuringCheck 為 true、各分頁列數一致，手工抽查內容。清除這三個臨時指令碼屬性。工具只核對預期欄位的 getValues，不核對公式、格式、父層共用或其他專案索引，不能取代獨立整庫演練；不得把控制表備份直接當正式控制表。獨立測試控制表須人工逐一 remap 至測試月檔後驗收，禁止指向正式資料。

## 4. 回退與上線閘門

發現問題：停止新入口寫入，確認所有執行停止、保留原始待同步與備份，記錄錯誤。核對舊版本與 schema 相容後，在測試環境先驗證，再由公司持有者恢復經核對的部署；不得直接用備份覆寫現行控制表。逐一測試登入、資料讀取與寫入，再恢復。若無相容回退方案，維持停寫並人工處理。所有必要項目實測通過、公司確認風險及交接責任後才能發布正式 v1.0.0。
