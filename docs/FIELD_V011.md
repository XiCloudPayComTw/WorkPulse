# WorkPulse v0.11.0｜外勤模式與工作類型操作

## 全站預設人員

首次開啟網站時選擇名單的第一人。右上角顯示目前選定人員姓名的最後兩個字，點擊可以展開柔和浮凸風格的人員清單。使用者手動切換後，瀏覽器本機保存穩定的員工 ID；日誌填寫、出勤、歷史查詢、統計報表都以這位人員為預設。下次重新整理或切換頁面時不會自行重置為第一位。

如果人員已被管理員停用或移除，才會自動選擇現有名單中的有效人員。切換前未提交草稿會保存在原人員的本機草稿位置。點選他人的歷史日誌進入編輯，也會明確切換人員。

**注意：選擇姓名只是方便使用的介面偏好，並不是員工登入或身分驗證。** 共用裝置上的任何使用者仍可能切換姓名。

## 手機外勤使用

當畫面寬度 900px 或以下：
- 工作總覽首頁改成大型全版功能卡，直接選「出勤表」、「填寫工作日誌」、「歷史紀錄」。管理員另外可進「管理員控制台」。
- 手機底部導覽排除「統計分析」與「系統設定」；這兩項仍在桌面可用。使用手機直接連結到上述兩頁，也會回到外勤首頁。
- 手機出勤表隱藏「薪資基準 · 即時計算」及「加班費計算公式（勞基法）」；真正的出勤、請假、工時欄位與歷史明細正常保留。會計試算和 Excel 匯出仍需桌面版操作。
- 雲端資料請求若超過短暫等待才顯示果凍感載入浮層，覆蓋網頁並提示正在讀取或儲存，避免在外勤訊號不穩時誤以為已完成。既有讀取 60 秒、寫入 90 秒逾時規則保持不變。寫入請求不會自動重新送出。
- 執行內容欄有可點選的文字歷史建議，分人員、分裝置的 localStorage 紀錄；在輸入與離開欄位或正式儲存時更新，最多保留 35 筆。不同電腦或不同瀏覽器不會自動同步建議內容。

## 工作類型設定及資料相容

工作項目第一欄改成「工作類型」，接著是「所屬專案」、「執行內容」、「成果」、「狀態」、「投入工時」。舊系統的 `title` 工作名稱欄位為保持 Google Sheets 結構相容，仍保留在儲存資料中；新工作項目預設由工作類型填入，同時保留舊紀錄原有的標題。

本機展示版可在桌面「系統設定」新增與編輯工作類型，過去本機日誌與常用範本的類型名稱同步更新。公司雲端管理員版新增「工作類型」分頁，只有授權管理員能修改名稱，設定寫入原公司控制工作簿的 Meta（`workCategories`、`workCategoriesRevision`）。每次更新都使用 lock、revision、requestId 及 Audit。已儲存的雲端歷史類型保留原樣，重新編輯其原日誌時可以保留舊類型；建立新日誌只能選目前類型。

正式公開 Apps Script 僅包含類型讀取函式；修改端點 `wpOwnerSaveCategories` 僅在獨立管理員封包內。

## 全部功能概況

- 工作總覽：工作摘要、最近工作日誌、完成概況（手機改外勤操作入口）。
- 工作日誌：選擇員工與日期、多筆工作類型／專案／執行內容／成果／狀態／投入時數、同日修改、草稿自動暫存、上次紀錄複製、常用範本、文字歷史建議。
- 歷史資料：按日期群組、月份切換、姓名／進度／關鍵字查詢、編輯既有紀錄。正式雲端由管理員刪除時需二次確認並記錄 Audit。
- 出勤表：日期與星期、上下班、休息、實際工時、加班時數、請假與備註、月度彙總、管理員應出勤天數設定。
- 桌面會計工具：輸入不會傳回 Google Sheets 的當次月薪、上月自動期間、跨月份試算、專業 Excel 三工作表匯出，包含法定加班費倍率與人工核對提醒。
- 桌面統計分析：期間／人員／專案／類型查詢、CSV／XLSX、時數及進度報表。
- 系統與名單：本機人員、專案、工作類型編輯，JSON 備份與 CSV 匯出；公司雲端由管理員維護人員與專案與工作類型，管理員二次確認刪除。
- Google Sheets：正式 Apps Script 後端預期使用公司管理者帳號持有的控制表及每個月份的獨立試算表。GitHub Pages **僅本機展示**。

## 安全、部署限制

- 本批是程式功能與 UI 交付，**沒有登入公司 Google Workspace 進行實際 Apps Script 發布，也沒有擅自建立、清理或改寫公司 Drive 內容**。正式雲端部署仍須公司擁有者授權、公開／私人入口分離驗證、正式多人使用測試。
- 一般介面禁止文字選取與複製，但輸入框／文字編輯欄仍允許選取、修正及複製。這不是 DRM 或安全權限，使用者仍可透過開發者工具、截圖或 API 取得原本可存取的內容。
- 瀏覽器記憶的工地執行內容僅保存在當下裝置，**如果是共用裝置，請避免填入客戶機密資料**；想清除可以使用瀏覽器網站資料清除功能。草稿與建議不等於 Google Sheets 的已提交資料。
- 手機出勤頁隱藏會計工具並非移除後端 API。只有公司的權限設定及資料存取政策可以真正限制資料的使用者；純 CSS 隱藏並不構成安全保護。
