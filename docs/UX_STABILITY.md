# WorkPulse v0.5.0 — 版面穩定性及操作驗收

## 設計原則

- 導覽欄不得因切換選單、顯示長姓名、長說明或頁面內容變動而擴張。桌面以 264px 固定欄；1220px 以下以 232px 固定欄；900px 以下改為手機底部導覽。
- 文字提升約一級：主要內容約 15–16px、輸入欄位 16px；少量眉標／輔助文字約 12–14px。卡片和按鈕內允許換行或省略，不得把主容器擠出 viewport。
- 選單目前所在頁：對比更明顯的灰藍色內凹底板、左側細線和略高字重。手機已選分頁同樣具底色和內凹陰影。統計快速日期選擇與團隊頁籤有同一致選狀態，並保留 aria-current／aria-pressed／aria-selected。
- 以 `transform` / `opacity` 作微動態；偏好 reduced-motion 的裝置關閉多數動畫。

## 已執行驗證

- `npm run verify`：40 / 40 Node 測試通過；含資料模型、Apps Script 權限模型、報表 XLSX、安全處理與 7 項快速填寫測試。
- Chromium 離線注入完整 Apps Script 打包 HTML：一般頁在 320、375、390、600、768、900、901、980、1024、1220、1440、1920px 切換；沒有偵測到頁面水平溢出或 JS 錯誤。
- 模擬極長姓名／案場名稱／工作標題／備註：320、375、390、768、900、901、980、1024、1280、1440px 各頁測試；側欄寬度與主內容起點沒有因切換頁面變動。
- 模擬 Google Apps Script 登入（**非實際 Workspace 身分驗證**）：320、390、768、900、901、1024、1440、1920px 檢查團隊管理三個頁籤與其他頁，未偵測到水平溢出。
- 互動測試：複製最近一筆同人工作、重設既有進度／工時／成果、暫存草稿、重新開頁還原、常用項目新增與再次使用、Ctrl/Cmd+S 正式儲存、Ctrl/Cmd+Enter 新增工作、正式提交後移除草稿。

## 雲端界線與例外

- 雲端版透過 `Session.getActiveUser` 由 Apps Script 判斷真正帳號權限；瀏覽器草稿及範本只能作便利功能，**不等於雲端同步成功**。
- 雲端失敗不能降級成無權限本機寫入。若公司需要跨裝置草稿、離職後資料保留、法遵銷毀期限，應獨立設計經驗證的後端草稿 API。
- 本次不調整工作日誌或 Sheets schema v3，無資料遷移。若尚未建立真實 Sheets，請先依 [`GOOGLE_SHEETS_DEPLOYMENT.md`](GOOGLE_SHEETS_DEPLOYMENT.md) 完成授權與實際驗收。
