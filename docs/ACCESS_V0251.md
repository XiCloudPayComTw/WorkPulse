# WorkPulse v0.25.1｜固定人員模式

2026-11-27 使用者要求取消員工自助新增及切換，管理員統一維護名單。基準 #41 main 935c3c2，CI #45966520654：206/206 Node、60/60 Chrome、7/7 GAS 通過。新版候選待 CI、使用者手動合併及實機驗收。

## 行為

- 管理員由私人 Script Properties 的 WORKPULSE_ADMIN_EMAIL 指定，須等於公司持有者且 active/effective 雙驗證，不依姓名提升權限。管理員在管理員控制台新增、停用及管理全部人員，保留必要跨人員管理操作。
- shared-code 員工免 Google 登入。正碼只返回可選的啟用人員名單及 5 分鐘一次性選擇 grant；選定後伺服器簽名發行 30 天固定人員憑證。短期 grant 重送同一人員去重，不同人員拒絕；全域最多 25 個未到期已綁定 grant，過期自動於後續綁定時清理。已綁定的 token 不可再綁定。
- 既有員工 RPC 僅接受已綁定的憑證；bootstrap 只回傳該員工、日誌查詢只回傳本人、出勤及日誌寫入驗證目標，報表限制同一人員。停用人員後拒絕操作。移除 wpSelfCreateEmployee RPC。維持管理員雙驗證、寫入鎖、停寫、requestId/revision 與 schema；不刪除舊資料。
- 右上姓名為靜態顯示，員工沒有新增/切換。重新登入使用已記憶的人員；已停用/不存在則提示聯絡管理員。舊版 v0.25.0 token 不相容，需重輸存取碼。若先前已有選擇，保留該選擇。
- 限制：共用碼並非本人身分驗證。新裝置、清除/修改瀏覽器資料、另開無痕視窗仍可重新選擇，不承諾阻止冒名；若要真正限制到本人，需獨立個人憑證。舊 domain 相容/回退入口不具固定人員伺服器綁定，正式員工只使用 shared-code。管理員保留全名單管理。瀏覽器記憶受儲存政策限制。

## 更新與驗收

1. 待 PR/main CI 通過後下載新 unified ZIP，原 TEST 備份，替換三檔並更新原部署版本，保留現有五項及兩組秘密、原 ID，勿重初始化。先核對管理員，若匿名部署無法取得 active email 則回退 domain；不能降低管理驗證。
2. 管理員控制台新增合成人員 A、B，員工首次輸入碼選 A；重開、跨頁、重新驗證仍 A，無新增或切換入口。用有效 A token 直接嘗試綁 B、讀寫 B、呼叫舊自助與管理 RPC 都應拒絕。確認管理員仍可管理兩人、停用 A 後 A 不能讀寫。
3. A01–A17 實測與公司簽認前仍為 TEST，不用真實資料。舊部署若有多個可訪問版本應停用；舊版不會執行新固定限制。
